How To

FeedEcho watches your RSS feeds and posts new items to Mastodon, Bluesky, micro.blog, Matrix, or email. Everything is built from three pieces: feeds, accounts, and echoes.

1. Add a feed

A feed is any RSS, Atom, or JSON feed URL — a blog, a news site, a podcast, a subreddit.

  1. Open Feeds.
  2. Paste the feed URL into the Add feed form.
  3. Set the poll interval — how often FeedEcho checks for new items (default 15 minutes). Lower intervals check more often; keep this reasonable for the feed's server.
  4. Click Add. FeedEcho records the newest item without posting it, so adding a feed never floods your accounts with the existing backlog.

Some sites don't publish a feed link. If the URL loads in a feed reader, it works in FeedEcho. Search engines can help: try site:example.com rss.

2. Add an account

An account is a destination FeedEcho can post to. Five kinds are supported.

Mastodon

  1. Open Accounts.
  2. Under Connect Mastodon via OAuth, enter your instance URL (for example https://mastodon.social).
  3. Approve the authorization prompt on your instance. The account is added automatically.

Bluesky

  1. In the Bluesky app, open Settings → Privacy and security → App passwords and create one.
  2. Under Connect Bluesky, enter your handle and the app password.
  3. Click Connect. The handle is resolved to your personal data server automatically.

Micro.blog

  1. Create an app token at micro.blog/account/apps (Account → Edit Apps → Add Token).
  2. Under Connect Micro.blog, paste the token. FeedEcho finds every blog the token can post to and connects each one.
  3. Use the Test button to confirm the token before relying on it.

Matrix

  1. Decide which Matrix account posts the items (a dedicated bot account is tidier than your own) and make sure it is in the target room — FeedEcho posts as that account and never joins rooms itself.
  2. Copy that account's access token. In Element: Settings → Help & About → Access Token.
  3. Under Connect Matrix, enter the homeserver (for example https://matrix.org), the token, and the room ID or alias (#feeds:example.org). Connect one room per submission; the same token can be reused for other rooms.
  4. Use the Test button to confirm the token and room membership before relying on it.

Email

  1. Under Add email account, enter a name and the destination address.
  2. In Settings, configure SMTP so FeedEcho can send on your behalf.
  3. Use the Test button to confirm delivery before relying on it.

3. Create an echo

An echo connects one feed to one account with rules for what gets posted.

  1. Open Echoes and click New echo.
  2. Pick the feed and the account.
  3. Write a template for the post. Variables like {{ '{{ title }}' }} and {{ '{{ link }}' }} pull from each feed item — the Echoes page lists the full set of available variables.
  4. Optional rules:
    • Filter keywords — post only items containing a keyword, or skip items containing it.
    • Content warning — for Mastodon, adds a spoiler label and marks posts sensitive.
    • Digest — email destinations only; batches items into one email per hour instead of sending per item.
  5. Save. New feed items post on the next poll, up to the drip limit you set.

Good to know

  • History keeps a record of every post and every failure, with retries for transient errors.
  • Deleting a feed or echo is soft: history is preserved.
  • Failure alerts: configure a notify email in Settings to hear about repeated failures.
